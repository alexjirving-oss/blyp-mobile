# ACCEPTANCE — Blyp Live Broadcasting (V1)

## PASS Gate (must all be true)
- Typecheck: PASS
- Lint: PASS
- Tests: PASS
- App runtime: no redbox; no fatal native exceptions; no duplicate view registration errors.
- Two-device scenario stable for 30 minutes.

## Acceptance Scenarios

### A1 — Two-Device Smoke (30 min)
Devices: Host phone + Viewer phone.
1) Host starts live.
2) Viewer joins within 10 seconds.
3) Viewer sees host video + hears host audio.
4) Host does not lose preview when viewer joins.
5) Run for 30 minutes:
	- No crashes
	- No video disappearing on either device
	- No memory leak symptoms (no runaway logs, no increasing fatal warnings)

### A2 — Guest Request/Approve
1) Viewer requests to join as guest.
2) Host receives request and approves.
3) Guest publishes audio/video.
4) Everyone sees guest tile.
5) Host can mute guest audio and it takes effect immediately.
6) Host can kick guest; guest is removed cleanly.

### A3 — Multi-Guest Scale (8 guests, 20 min)
1) Host + 8 guests in stage.
2) Maintain for 20 minutes.
3) Layout remains stable; no blank tiles; no render swap bug.
4) If bandwidth drops, at least audio remains stable.

### A4 — Reconnect
1) While live, toggle viewer network off for 10 seconds then back on.
2) Viewer auto reconnects and resumes receiving.
3) Repeat for guest network off/on:
	- guest rejoins and republish works
4) No duplicate track renderers after reconnect (no doubled audio, no ghost tiles).

### A5 — Chat + Moderation
1) Viewer sends chat messages; host sees them.
2) Moderator can:
	- slow mode on/off
	- delete message (if supported)
	- ban user (user cannot chat thereafter)

### A6 — Gifts
1) Viewer sends a gift to host; host receives event.
2) Viewer sends a gift targeted to a guest; guest receives event.
3) Server ledger updates and client reflects balance changes correctly.
4) No client-trust for balances or payouts.

## Evidence Required for PASS
- Saved logcat snippets showing:
  - join/publish events
  - remote track attach
  - reconnect success
- A short “run report” summary generated by automation with:
  - commit hash
  - test results
  - scenario results
